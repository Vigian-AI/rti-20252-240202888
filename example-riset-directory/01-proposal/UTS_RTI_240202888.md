## **A. JUDUL**

Perbandingan Throughput dan p95 Latency REST API Spring Boot vs .NET pada MongoDB

## **B. RINGKASAN**

Pemilihan framework backend sering ditentukan preferensi tim, padahal bukti empiris menunjukkan perbedaan kinerja yang relevan bagi biaya dan skalabilitas layanan. Studi komparatif yang ada umumnya berfokus pada database relasional atau konfigurasi lingkungan yang terbatas, sementara praktik modern banyak menggunakan database NoSQL seperti MongoDB. Penelitian ini bertujuan menguji apakah terdapat perbedaan signifikan pada throughput (RPS) dan p95 latency antara REST API yang dibangun dengan Java Spring Boot dan .NET pada operasi CRUD di MongoDB.  
Metode yang digunakan adalah controlled comparison study dengan dua implementasi API yang identik secara fungsional. Variabel independen adalah framework backend; variabel dependen adalah throughput dan p95 latency; variabel kontrol meliputi dataset seed, konfigurasi MongoDB, load profile, serta lingkungan eksekusi. Pengukuran dilakukan menggunakan alat load testing dan collector metrik, dengan prosedur warm-up dan window steady-state. Analisis statistik mengikuti uji normalitas dan uji beda dua kelompok, disertai effect size.  
Luaran yang ditargetkan adalah dataset hasil benchmarking terstruktur, analisis perbandingan yang valid secara statistik, serta rekomendasi berbasis bukti tentang trade-off kinerja kedua framework pada konteks NoSQL. Hasil diharapkan membantu praktisi dan peneliti mengambil keputusan yang lebih objektif, serta menjadi dasar replikasi pada konteks infrastruktur yang lebih luas.

## **C. KATA KUNCI**

Spring Boot; .NET; REST API; MongoDB; benchmarking

## **D. PENDAHULUAN**

### **D.1. LATAR BELAKANG DAN RUMUSAN MASALAH**

Dalam pengembangan layanan backend, pilihan framework berdampak langsung pada throughput, latensi, dan biaya infrastruktur (Godinho et al., 2024; Grzeszuk dan Milosz, 2025). Pengembang membutuhkan bukti terukur untuk menentukan trade-off tersebut, namun studi komparatif yang ada masih terbatas pada skenario dan data tertentu, termasuk penggunaan database relasional dan konfigurasi lingkungan yang sempit (Kronis dan Uhanova, 2018; Grzeszuk dan Milosz, 2025). Temuan perbandingan bahasa dan framework juga menunjukkan variasi kinerja yang signifikan, sehingga hasil antar studi bisa berbeda konteks (Rompis dan Aji, 2018; Hadiewijaya dan Wasito, 2024; Zulham et al., 2025).  
Apakah Spring Boot dan .NET menunjukkan perbedaan kinerja yang signifikan pada workload CRUD berbasis NoSQL (MongoDB) dalam kondisi eksperimen yang adil dan terkontrol, mengingat studi yang ada lebih banyak menguji konteks relasional atau review berbasis literatur (Godinho et al., 2024; Grzeszuk dan Milosz, 2025; Sirigiri, 2023). Jika perbedaan itu nyata, dampaknya adalah dasar pemilihan teknologi yang lebih objektif bagi tim backend, arsitek sistem, dan manajer proyek.  
Konteks penelitian ini berada pada lingkungan layanan REST API modern yang berinteraksi dengan database NoSQL, dengan fokus pada pengujian terkontrol untuk memastikan validitas internal dan fairness perbandingan.

### **D.2. PENDEKATAN PEMECAHAN MASALAH**

Penelitian ini bertujuan membandingkan kinerja Spring Boot dan .NET pada operasi CRUD terhadap MongoDB. Apakah terdapat perbedaan signifikan pada throughput (RPS) dan p95 latency antara kedua framework pada kondisi eksperimen yang identik, dengan Hipotesis awal menyatakan adanya perbedaan signifikan pada kedua metrik tersebut.  
Intervensi penelitian berupa pergantian framework backend (Spring Boot vs .NET) dengan API yang identik secara fungsional, sementara dataset, konfigurasi DB, load profile, dan environment dijaga tetap. Baseline dan treatment ditetapkan secara simetris agar perbandingan fair.

### **D.3. STATE OF THE ART DAN KEBARUAN**

Kajian terdahulu menunjukkan tren studi benchmarking API, namun banyak menggunakan database relasional, versi teknologi yang cepat usang, dan lingkungan uji yang sempit (Kronis dan Uhanova, 2018; Godinho et al., 2024; Grzeszuk dan Milosz, 2025). Beberapa studi melaporkan .NET unggul pada response time, sementara Spring Boot lebih stabil di bawah beban tinggi, tetapi konteks NoSQL belum banyak dieksplorasi (Godinho et al., 2024; Grzeszuk dan Milosz, 2025; Sirigiri, 2023).  
Gap yang diidentifikasi adalah kombinasi method, data, dan context gap: kurangnya perbandingan pada database NoSQL modern (MongoDB) serta minimnya pengujian dalam setup yang terkontrol dan terdokumentasi ketat. Penelitian ini memposisikan diri sebagai perbandingan terukur pada konteks NoSQL dengan fairness dan threat analysis yang eksplisit.  
Kebaruan yang ditawarkan adalah eksperimen terkontrol pada workload CRUD berbasis MongoDB dengan metrik primary yang jelas (RPS dan p95 latency), disertai rencana statistik dan mitigasi ancaman validitas sejak awal.

### **D.4. PETA JALAN PENELITIAN**

Tahap yang telah dicapai mencakup pemetaan literatur, identifikasi gap, perumusan RQ dan hipotesis, definisi variabel dan metrik, serta pemetaan sistem ke variabel eksperimen. Tahap yang dikerjakan pada usulan ini adalah pembangunan artefak eksperimen, pelaksanaan benchmarking terkontrol, dan analisis statistik hasil.  
Tahap lanjutan yang direncanakan meliputi replikasi pada variasi ukuran dataset dan konfigurasi infrastruktur tambahan, serta perluasan konteks ke arsitektur yang lebih kompleks seperti container orchestration.

## **E. METODE**

### **E.1. Desain Penelitian dan Unit Analisis**

Penelitian ini merupakan comparison study dengan desain eksperimen terkontrol. Unit analisis adalah hasil run benchmarking pada dua implementasi REST API yang identik secara fungsional. RQ menilai perbedaan throughput dan p95 latency antara Spring Boot (control) dan .NET (treatment) pada operasi CRUD MongoDB.  
Konteks penelitian adalah layanan REST API pada beban kerja terstandar dengan lingkungan eksekusi yang identik. Outcome yang dituju adalah bukti perbandingan kinerja yang dapat diuji secara statistik dan direplikasi.

### **E.2. Variabel, Metric, Instrumen, dan Data**

Variabel independen utama adalah framework backend (Spring Boot vs .NET). Variabel dependen adalah throughput (RPS) dan p95 latency (ms) sebagai metrik primary. Variabel kontrol meliputi dataset seed dan skema MongoDB, konfigurasi instance DB, load profile, serta vCPU/RAM dan network setup.  
Instrumen pengukuran berupa load testing tool untuk menghasilkan RPS dan latency, serta metrics collector untuk menghimpun hasil per run. Justifikasi metrik: RPS merepresentasikan kapasitas sistem, sedangkan p95 latency menangkap responsivitas tail, keduanya memiliki skala ratio dan relevan dengan tujuan RQ.

### **E.3. Skenario dan Prosedur Pengujian**

Skenario pengujian membandingkan dua API yang identik secara fungsi dengan mengganti framework backend sebagai satu-satunya IV. Prosedur meliputi penyiapan dataset dan konfigurasi MongoDB yang sama, warm-up terstandar, eksekusi load profile yang identik, pengambilan metrik pada window steady-state, dan pengulangan run untuk replikasi.  
Fairness dijaga dengan environment identik, konfigurasi eksplisit, dan dokumentasi penuh parameter eksperimen. Replikasi dilakukan dengan jumlah run yang memadai untuk mendukung uji statistik.

### **E.4. Artifact, Setup, atau Kesiapan Implementasi**

Artifact penelitian adalah dua implementasi REST API (Spring Boot dan .NET) dengan kontrak endpoint dan logika CRUD yang setara, sebuah instance MongoDB dengan dataset seed tetap, serta pipeline pengujian yang mencakup load generator dan metrics collector.  
Setup ini diposisikan sebagai instrumen eksperimen: framework backend memetakan variabel independen, collector metrik memetakan variabel dependen, dan konfigurasi lingkungan memetakan variabel kontrol agar isolasi variabel terjaga.

### **E.5. Teknik Analisis, Asumsi, dan Validitas**

Data dianalisis dengan uji normalitas; jika distribusi normal digunakan independent t-test, jika tidak digunakan Mann-Whitney U. Effect size dilaporkan untuk menilai signifikansi praktis, dengan alpha 0.05. Interpretasi hasil dilakukan dengan membandingkan perbedaan rata-rata metrik dan interval kepercayaan.  
Asumsi utama meliputi kestabilan lingkungan eksekusi, kesetaraan implementasi fungsional, serta ketersediaan jumlah sampel run yang cukup. Ancaman validitas utama adalah variabilitas runtime dan noise resource (internal), keterbatasan generalisasi ke konfigurasi lain (external), representasi metrik terhadap kualitas layanan end-to-end (construct), dan power statistik rendah (conclusion). Mitigasi mengikuti desain eksperimen dan replikasi yang terencana.

## **F. HASIL YANG DIHARAPKAN**

Hasil yang diharapkan adalah dataset benchmarking terstruktur berisi RPS dan p95 latency untuk kedua framework pada skenario CRUD MongoDB, lengkap dengan metadata konfigurasi. Dari data ini dihasilkan kesimpulan komparatif yang valid secara statistik dan rekomendasi pemilihan framework berdasarkan trade-off kinerja.  
Luaran tambahan berupa dokumentasi eksperimen yang dapat direplikasi serta bahan publikasi atau laporan teknis yang merangkum metodologi, hasil, dan keterbatasan penelitian.
